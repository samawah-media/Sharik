## النطاق

طلب المالك: مراجعة 3–4 مراجع سعودية، دليل لغة سعودية مختصر، وثلاثة نماذج للمراجعة قبل تعديل كود المنصة. المخرجات هنا تصورات مستقلة وليست واجهات منشورة أو دليل نجاح وظيفي.

النماذج: لوحة الإدارة، مساحة المخرج الداخلية، وموافقة العميل. بيانات وأسماء ورسوم تجريبية فقط. لا اتصالات شبكة أو تسجيل دخول أو حفظ أو رفع أو اعتماد حقيقي.

## الحدود

- لا تعديل لـ src أو scripts أو tests أو Supabase أو الحزم.
- لا تغيير للصلاحيات أو دورة الاعتماد أو SLA أو حساب الباقة.
- لا نشر أو commit/push أو دعوات خارجية.
- حفظ أعمال D17/D18 السابقة دون تغيير أو إعادة تصنيف.
- البنود العشرون في قائمة متطلبات قبول المالك تبقى غير مؤشرة؛ هي تدقيق متطلبات، لا عشرون اختبارًا تشغيليًا بالضرورة.
- الموافقة على النموذج لا تعني OWNER_UAT_PASS أو جاهزية الفريق.

## معايير مراجعة النماذج

1. اللغة سعودية خفيفة؛ الإجراء الحساس دقيق ويرتبط بالنسخة.
2. واجهة RTL من 375 إلى 1440 بكسل دون تمرير أفقي للصفحة.
3. كل إجراء ظاهر في النموذج هدفه 44 بكسل على الأقل، وتركيز لوحة المفاتيح واضح.
4. الفرق بين بيانات غير متاحة وصفر حقيقي ظاهر في توصيات التصميم.
5. الرسم يجيب عن سؤال ويطابق الأرقام التجريبية؛ لا اتجاهات أو نسب نمو بلا سجل زمني.
6. العميل لا يتلقى مفاهيم المراجعة الداخلية أو تفاصيل الفريق.
