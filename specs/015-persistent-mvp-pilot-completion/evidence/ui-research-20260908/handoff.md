# انتقال آمن من النموذج إلى المنتج

تحديث 2026-09-08: اعتمد المالك النماذج وطلب بدء التنفيذ؛ أصبحت
[خطة UI1](../ui1-plan.md) نطاق الدفعة التنفيذية الأولى. التوصيات أدناه هي
خريطة الانتقال، وليست إثبات اكتمال التنفيذ أو تصريح نشر.

## ترتيب الاعتماد

1. يراجع المالك النماذج والألفاظ ويحدد قبول الاتجاه أو تعديلاته.
2. يُفصّل التغيير المعتمد في spec/plan/tasks القائمة. لا يبدأ تغيير src قبل ذلك.
3. جرد المكونات والمفاتيح النصية الفعلية، مع فصل النص الثابت عن المحتوى الذي كتبه المستخدم.
4. تطبيق المكونات المشتركة أولًا في دفعة محددة، ثم لوحة الإدارة، ثم مساحة المخرج، ثم بوابة العميل.
5. مراجعة واختبارات بعد كل دفعة؛ الحفاظ على جميع الحقول والإجراءات المحمية الحالية، لا اعتبار النموذج المختصر قائمة وظائف بديلة.
6. فحص النسخة المجمعة، ثم exact-HEAD CI وPreview المصرّح به، ثم دليل تجربة المالك.

## حدود التنفيذ المقترحة

- مكونات العرض والنصوص فقط. ممنوع تغيير RLS وAuth وSQL وServer Actions والانتقالات والحسابات لتناسب الرسم.
- لا استبدال Drawer بصفحة جديدة بسبب أن النموذج يعرضه في مساحة مستقلة. الشكل النهائي يركب داخل السطح الحالي ويحافظ على التركيز والحقول والقيم عند الخطأ.
- نموذج العميل منفصل سياقيًا عن الإدارة، لكن الملف التجريبي يحتوي أمثلة الأدوار كلها؛ هذا ليس إثبات عزل بيانات أو صلاحيات.
- الأيقونات الأصلية والرسوم الهندسية في النموذج للتوضيح؛ لا أصول أو كود من المنافسين. أي خط أو مكتبة جديدة تحتاج فحص الترخيص والقرار المطلوب قبل إدخالها.
- لا شراء خطوط أو صور أو اشتراكات، ولا استخدام رصيد API مدفوع إضافي دون موافقة.
- فشل البيانات يُعرض كفشل، وليس أرقامًا صفرية. لا إخفاء قيود أو حالات متأخرة بالتجميل.

## الرسوم البيانية

| الرسم المقترح | البيانات اللازمة | شرط التطبيق |
| --- | --- | --- |
| توزيع المخرجات | عدد حالات متنافية داخل نفس النطاق | مطابقة مجموع الشرائح للإجمالي؛ لا جمع «متأخر» مع حالات العمل لأنه وصف متداخل |
| المسلّم لكل عميل | عدد المسلّم وإجمالي المخرجات لنفس العميل والفترة | ليس استهلاك الباقة ولا متوسط نسبة التقدم |
| المتاح من الباقة لاحقًا | إسقاط ledger الحالي | عرض وحدات الخدمة بوضوح، لا جمع ساعات ومنشورات في نسبة واحدة |
| اتجاه الأداء مع الوقت | سجل زمني وتعريف ثابت للمؤشر | مؤجل؛ لا اختراع نقاط زمنية من لقطة الحالة الحالية |

النموذج يستخدم 24 مخرجًا: 12 مسلّمًا + 6 قيد التنفيذ + 4 بانتظار العميل + 2 للمراجعة الداخلية. المتأخران مجموعة فرعية من قيد التنفيذ. مجموع العملاء 10+8+6=24 والمسلّم 6+4+2=12. لا تمثل هذه أرقام المنصة.

## دليل المالك الواحد — خطة التجميع

يبقى [دليل تجربة المالك](../owner-acceptance-walkthrough-ar.md) نقطة البداية، ولا ننشئ ملف نتائج منافسًا له. عند اعتماد وتنفيذ التصميم، يحدّث الدليل نفسه بجولات الأدوار ثم إعادة اختبار إصلاحات الصور ثم تجربة التصميم واللغة. الروابط تحتفظ بسجل المتطلبات والعيوب القديم.

قائمة CHK001–CHK020 تدقق اكتمال المتطلبات، لا نجاح البرنامج وحده. الخريطة التالية مقترحة لتجميع الأدلة، وجميع النتائج **لم تُنفّذ** في هذه الدفعة:

| بنود المتطلبات | موضعها المقترح في الدليل الواحد | نوع الدليل |
| --- | --- | --- |
| CHK001، CHK006 | إعادة العمل للتعديل الداخلي | تعريف الانتقال، ثم تجربة منفصلة بسجل القرار والنسخة |
| CHK002 | لوحة العمل | تعريف السحب والأوامر المحمية، ثم تجربة النجاح والمنع |
| CHK003، CHK007 | الفريق والدعوات | تعريف الأدوار والنطاق، ثم اختبار الدعوة والحساب المعطّل |
| CHK004 | تجهيز بيئة الاختبار | مراجعة خطة rollover وحفظ Audit/Ledger؛ تنفيذ تقني بإذن مستقل |
| CHK005 | موافقة العميل | ربط القرار بالنسخة والتاريخ الصحيح |
| CHK008 | قنوات الإشعار | توثيق نطاق البريد المعتمد وعدم افتراض الإرسال |
| CHK009 | ملخص التغطية | مراجعة تطابق سجل العيوب والمهام والنتائج |
| CHK010 | الجولات حسب الدور | نتائج منفصلة للإدارة ومدير الحساب والفريق والمشاهد والمعتمد |
| CHK011 | التصميم واللغة والوصول | desktop 100%، mobile، RTL، لوحة المفاتيح |
| CHK012 | قواعد إيقاف الجولة | P0/P1 توقف، وقرار موثق لـP2 |
| CHK013، CHK019 | شروط البدء | Preview مطابق SHA، حسابات فعلية ومهاجرات مراجعة، دون أسرار في الدليل |
| CHK014 | الاسترجاع والتكرار | stale state، lost response، retry، no-op، rollback بإعداد تقني آمن |
| CHK015 | الأمان | Client A/B، مشاهد/معتمد، سرية الداخلي |
| CHK016 | الملفات | الرفع والفشل والإلغاء والاستئناف والمعاينة والتنزيل |
| CHK017 | الحالات غير السعيدة | تحميل، فراغ، خطأ قراءة، بيانات قديمة، إعادة محاولة |
| CHK018 | رحلة التسليم والباقة | الحجز والاستهلاك وتوقف/استئناف SLA والتكرار الآمن |
| CHK020 | قرار المالك وحدود الإطلاق | عدم خلط قبول التصميم بقبول المنتج أو Production |

إضافات التصميم المقترحة في نفس الدليل: فهم المصطلحات، تحديد الإجراء التالي، مقروئية الحالات، تطابق أرقام الرسوم مع البيانات، قراءة النص الطويل، وضوح النسخة قبل القرار، وغياب التنقل المضلل. لا عدد نهائي للسيناريوهات قبل جرد الإصلاحات وربطها؛ ولا علامة PASS استنادًا إلى النموذج.

## قواعد التفويض والتكلفة

البحث البصري ودليل اللغة فُصلا في مهمتين مستقلتين، والتصميم والدمج والفحص عند القائد. Gemini أُدرج كمرشح، لكن محاولتي إطلاق relay مُنعتا قبل تشغيله؛ لا نسلّم تقريره على أنه استُخدم. لا نكرر أو نتحايل على رفض الأمان. مسودة اللغة نُفذت داخل Codex بواسطة Astra. التكلفة المالية والاستهلاك غير المبلّغ عنهما: غير معروفين، وليسا صفرًا. لا تحتاج هذه الدفعة وكيلًا إضافيًا أو شراء خدمة.
